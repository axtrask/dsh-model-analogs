# dsh-model-analogs

Добавляет модели в DSH «по аналогии»: выбираешь модель из установленного каталога
pi-ai, задаёшь новый id — плагин копирует возможности аналога и записывает модель
в конфиг профиля.

## Зачем

Страница **Settings → Models** умеет добавлять модель только по строке из
каталога: для id, которого в каталоге нет (новая модель провайдера), приходится
вручную указывать контекст, maxTokens, модальности и уровни ризонинга. Плагин
делает из этого один выбор и заодно сам пишет конфиг.

## Как это работает

- Карточка на странице Models (слот `settings.models.footer`) читает каталог через
  `ctx.llm.listModels` и возможности аналога через `ctx.llm.resolveModelInfo`
  (контекст, модальности, набор уровней ризонинга).
- Запись идёт через `ctx.settings.update('llm-pi-ai', …)`: правка попадает в
  `profiles/<profile>/cordis.patch.yml` под строку `llm-pi-ai`, валидируется её
  схемой и применяется на лету.
- Модели живут на **отдельном роуте** (`openrouter-analog` по умолчанию), а не на
  `openrouter`: в llm-pi-ai список `models` заменяет каталог роута целиком, поэтому
  дописывание одной модели в `openrouter` потребовало бы выгрузить туда все ~400
  его моделей.

## Установка

Плагин подключается к профилю DSH как обычный bundle — копировать файлы и создавать
junction вручную не нужно.

### Из Git

Добавить пакет в зависимость профиля:

```sh
cd <profile>
pnpm add git+https://github.com/axtrask/dsh-model-analogs.git
```

Затем в `profiles/<profile>/package.json` добавить `"dsh-model-analogs"` в
`dsh.profile.bundles` и перезапустить профиль (`dsh web`).

Второй путь — попросить агента вызвать `plugin_manager` с `install_bundle` и тем же
Git-адресом: он сам поставит пакет и включит bundle.

### Из локального чекаута

Для разработки пакет можно привязать ссылкой: `"dsh-model-analogs": "link:<абсолютный
путь к чекауту>"` в `dependencies` профиля плюс `pnpm install`. Правки применяются
после перезапуска профиля: правка конфигурации уже смонтированных плагинов проходит
на лету, но новая строка-плагин монтируется только при старте.

## Конфиг (`cordis.patch.yml`)

| поле | смысл |
|---|---|
| `settingsNs` | запись в какого плагина получает роут (`llm-pi-ai`) |
| `catalogRoute` | откуда берутся аналогии (`openrouter`) |
| `route` / `routeName` | ключ и подпись создаваемого роута |
| `apiKeyEnv`, `baseURL`, `api` | как роут ходит в провайдера |
| `thinkingFormat`, `offWire`, `supportsDeveloperRole`, `supportsStrictMode` | wire-переключатели ризонинга |
| `defaultMaxTokens` | запасной лимит ответа, когда у модели свой не задан |
| `path` | HTTP-канал карточки (`/model-analogs/api`) |

## Ограничения

- Каталогом не публикуется `maxTokens` (seam отдаёт его только для моделей, у
  которых лимит задан в конфиге), поэтому в карточке есть поле `maxTokens`
  со значением из `defaultMaxTokens`.
- `Restore default models` на странице Models и ручное удаление роута убирают
  модели плагина — вернуть их можно, добавив заново в карточке.
- Аналогия берётся из установленного каталога pi-ai: если каталог ещё не знает
  новую модель, это и есть штатный сценарий — её добавляют «по аналогии» с
  предыдущей.
